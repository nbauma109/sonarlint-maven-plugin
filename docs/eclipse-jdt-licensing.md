# Eclipse JDT license compatibility

The Maven plugin's code remains GNU General Public License, version 3 only
(GPL-3.0-only). The bundled Eclipse Java Development Tools (JDT) Core and Core
Manipulation libraries and certain Eclipse Platform dependencies are distributed
under the Eclipse Public License, version 2.0 (EPL-2.0).

## Compatibility mechanism

The [Eclipse Foundation's licensing commentary](https://blogs.eclipse.org/post/mike-milinkovich/eplgpl-commentary)
and the [Free Software Foundation's GNU license FAQ](https://www.gnu.org/licenses/gpl-faq.html#GPLIncompatibleLibs)
both identify an **additional GPL linking exception authorized by the
copyright holders** as a solution for combining a GPL program with
EPL-licensed libraries. EPL-2.0 is not inherently GPL-compatible;
the existence of an optional EPL secondary-license mechanism is not itself
a secondary-license grant for a particular artifact.

This project therefore includes
[ECLIPSE-JDT-LINKING-EXCEPTION.md](../ECLIPSE-JDT-LINKING-EXCEPTION.md),
an additional permission under GPL version 3, section 7, specifically for
JDT Core, JDT Core Manipulation and their required EPL-2.0-covered Eclipse
Platform dependencies. The original [GPL text](../LICENSE) is unchanged.

The exception applies only where the relevant project copyright holders
authorize it; it cannot grant permission for third-party GPL code owned by
other parties. Eclipse libraries remain under EPL-2.0, and their corresponding
source, license and copyright notice obligations remain applicable.

For future copyrightable contributions to the Maven plugin, obtain an
express GPLv3 section 7 linking-exception grant from the contributor or
verify that the contribution is already licensed on compatible terms.
Do not assume the repository's exception applies to all incoming GPL code.

## Release requirements

1. Confirm that the persons or organizations owning GPL-covered original
   program code authorize this section 7 exception.
2. Inspect the complete runtime dependency inventory and per-module
   Maven license audit, generated as `eclipse-jdt-runtime-license-inventory`
   by the release-validation workflow. The audit rejects missing license
   declarations and unrecognized license names for Eclipse JDT and Platform
   artifacts; a passing report still needs review of actual source notices
   and license obligations.
3. Preserve the original Eclipse copyright and EPL-2.0 license notices,
   and provide corresponding source under the terms of the libraries.
   The GPL exception is **not** a relicensing of Eclipse components.
4. Verify the main binary includes `META-INF/LICENSE`,
   `META-INF/COPYRIGHT.md`, `META-INF/THIRD_PARTY_NOTICES.md` and
   `META-INF/ECLIPSE-JDT-LINKING-EXCEPTION.md`. The build checks these
   artifacts before publication.
5. Confirm that no third-party GPL code requiring independent permission
   is distributed as part of the combined plugin.

The publishing workflow should not be used until these obligations and
copyright permissions have been confirmed. Neither a successful build nor
a dependency license report constitutes a formal legal opinion.

## Why this option

This avoids changing the entire project to EPL-2.0, preserves existing
GPL-3.0-only user freedoms aside from the specific additional linking
permission, and retains the existing GNU Lesser General Public
License (LGPL)-licensed Sonar analyzer components under their original
licenses. The exception is limited to Eclipse JDT dependencies rather
than authorizing linking with arbitrary GPL-incompatible libraries.
